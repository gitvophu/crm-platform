## Spec

### Mục tiêu

Nhân viên đăng nhập bằng email + mật khẩu, mọi API (trừ `/health` và các endpoint đăng nhập) yêu cầu đăng nhập, web chuyển tới trang login khi chưa đăng nhập hoặc phiên hết hạn. Có module `identity` (user, team, role) và guard dùng chung cho mọi module sau.

### Trong phạm vi

- ADR-0004: auth bằng access token (JWT) + refresh token trong cookie httpOnly
- Module `identity` (schema `identity`): team, user (role `admin` / `manager` / `member`), session
- `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`, `GET /auth/me`, `POST /auth/change-password`
- Guard toàn cục (mặc định phải đăng nhập), decorator `@Public()`, `@CurrentUser()`
- Validation bằng zod: schema trong `@crm/shared`, pipe trong api (convention cho mọi module sau)
- Convention id: UUID v7 (`uuidv7()` của Postgres 18)
- `make seed`: 2 team, 4 user
- Web: trang login, quay lại trang cũ sau khi đăng nhập, tự refresh khi gặp 401, user menu trên header, trang Account đổi mật khẩu, đăng xuất

### Ngoài phạm vi

- Phân quyền theo dòng (slice 1.3), màn hình quản trị user/team (spec Q7)
- Chặn dò mật khẩu (rate limit): backlog, làm khi deploy (Q10)
- Quên mật khẩu, gửi email, đăng xuất mọi thiết bị, danh sách phiên
- Format lỗi API thống nhất (slice 1.3): 1.2 dùng lỗi mặc định của Nest

## Q&A

Trạng thái: ❓ Mở (có đề xuất, chờ chốt) · ✅ Đã chốt.

### Q1. Thời hạn token, gia hạn phiên?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)
- **Phương án:** một JWT 8h tự gia hạn, access 15 phút + refresh token, một JWT cố định 8h
- **Quyết định:** access token (JWT) 15 phút + refresh token lưu DB.
- **Lý do:** thu hồi được phiên (đăng xuất, đổi mật khẩu) mà guard vẫn không cần đọc DB. Phức tạp hơn một JWT, chấp nhận vì là điểm thực hành. Phase 1.5 (OIDC) thay thế.

### Q2. Guard có đọc user từ DB ở mỗi request?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)
- **Quyết định:** không. Guard chỉ verify JWT. Role, team lấy từ payload.
- **Hệ quả:** đổi role/team, thu hồi phiên có hiệu lực chậm tối đa 15 phút (thời hạn access token). `GET /auth/me` đọc DB để trả tên, email mới nhất.

### Q3. Kiểu id?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)
- **Phương án:** UUID v7, UUID v4, số tự tăng
- **Quyết định:** UUID v7, sinh bằng `uuidv7()` của Postgres 18 (`@default(dbgenerated("uuidv7()")) @db.Uuid`). Convention cho mọi bảng.
- **Lý do:** sắp theo thời gian nên index tốt, không đoán được, không lộ số lượng bản ghi.

### Q4. Validation input?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)
- **Phương án:** zod, class-validator, kiểm tra tay rồi chốt ở 1.3
- **Quyết định:** zod. Schema input đặt trong `@crm/shared` (web dùng lại cho form), api dùng `ZodValidationPipe`. Lỗi validation trả 400 mặc định của Nest, format thống nhất chốt ở 1.3.
- **Lý do:** đã dùng zod cho env, một schema cho cả api và web.

### Q5. Refresh token: thời hạn, xoay vòng?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)
- **Quyết định:**
  - Hết hạn khi không dùng 7 ngày (mỗi lần refresh tính lại), hết hạn tuyệt đối 30 ngày từ lúc đăng nhập (không gia hạn)
  - Xoay vòng: mỗi lần refresh cấp token mới, token cũ hết hiệu lực
  - Phát hiện dùng lại: token cũ bị dùng lại thì thu hồi cả phiên
  - DB chỉ lưu hash (SHA-256) của refresh token. Cookie httpOnly, `Path=/api/auth`, chỉ gửi tới các endpoint auth
- **Lý do:** theo OAuth 2.0 Security BCP. Hạn tuyệt đối 30 ngày để phiên không kéo dài mãi (yêu cầu của user).

### Q6. Web xử lý access token hết hạn?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)
- **Phương án:** gặp 401 thì refresh rồi gọi lại, hẹn giờ refresh trước khi hết hạn
- **Quyết định:** trong `api()`: 401 → `POST /api/auth/refresh` → gọi lại request một lần. Nhiều request cùng lúc chờ chung một lần refresh. Refresh fail → chuyển tới `/login?redirect=<trang hiện tại>`.

### Q7. Thư viện JWT, guard?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)
- **Phương án:** `@nestjs/jwt` + guard tự viết, Passport, `jose`
- **Quyết định:** `@nestjs/jwt` (HS256, secret `JWT_SECRET` trong env), guard toàn cục tự viết đọc cookie. Không dùng Passport, xem lại ở Phase 1.5.

### Q8. Thư viện argon2?

- **Trạng thái:** ✅ Đã chốt (2026-11-01)

- **Lý do:** binary dựng sẵn qua `optionalDependencies`, không chạy script cài đặt, không cần `allowBuilds`. Hash cùng định dạng với `argon2` nên đổi được về sau.

### Các quyết định nhỏ (đề xuất, chưa hỏi riêng)

- **Mật khẩu:** tối thiểu 8, tối đa 128 ký tự, không bắt buộc ký tự đặc biệt (NIST SP 800-63B). Email lưu chữ thường, so sánh không phân biệt hoa thường.
- **Đăng nhập sai:** luôn trả 401 `Invalid email or password`, không cho biết email có tồn tại hay không. Email không tồn tại vẫn chạy verify argon2 với một hash giả để thời gian trả lời như nhau.
- **CSRF:** cookie `SameSite=Lax` (trình duyệt không gửi cookie kèm POST từ site khác), web và api cùng origin. Đủ cho trình duyệt hiện đại, không thêm CSRF token.
- **Cookie:** `crm_access` (`Path=/api`), `crm_refresh` (`Path=/api/auth`), cả hai `HttpOnly`, `SameSite=Lax`, `Secure` (trình duyệt cho phép `Secure` trên `http://localhost`). Path có tiền tố `/api` vì trình duyệt thấy URL qua proxy của Vite.
- **Payload access token:** `sub` (user id), `sid` (session id), `role`, `teamId`.
- **Hai tab cùng refresh:** web dùng Web Locks API (`navigator.locks`) để các tab refresh lần lượt, tab sau gửi cookie mới. Server chấp nhận token vừa bị xoay trong 30 giây mà không coi là dùng lại (trả 401, không thu hồi phiên), để request đang bay không làm mất phiên.

## Ghi chú khi implement

Những gì lệch khỏi plan trong lúc làm, và lý do.

- **Seed chạy bằng `tsx`**, không chạy TS trực tiếp bằng Node: Prisma client sinh ra là file `.ts` nhưng import nhau bằng đuôi `.js`, Node không tự đổi. Thêm `esbuild: false` vào `allowBuilds` (script cài đặt của esbuild chỉ kiểm tra binary).
- **Tên bảng số nhiều** (`identity.users`, `teams`, `sessions`) và enum `identity.role`: `user` là từ khoá của Postgres, tên số nhiều tránh phải đặt trong ngoặc kép khi viết SQL tay. Ghi thành convention trong CLAUDE.md.
- **Mật khẩu hiện tại sai → 403**, không phải 401: 401 làm web hiểu là access token hết hạn rồi refresh và gọi lại.
- **CSRF:** bỏ ý "api chỉ nhận body JSON" (Nest vẫn parse form urlencoded). Dựa vào `SameSite=Lax` là đủ, đã sửa ADR.
- **`cookie-parser` đăng ký trong `IdentityModule`** (middleware), không ở `main.ts`, để test e2e (không chạy `main.ts`) cũng đọc được cookie.
- **`JWT_SECRET` cố định trong `vitest.config.ts`** của api: test không phụ thuộc `.env`, CI không cần secret. `.env` có sẵn từ trước phải thêm dòng `JWT_SECRET` (README).
- **Lỗi ở `refreshSession` vẫn gọi lại request một lần:** tab khác có thể vừa refresh xong, cookie mới đã có trong trình duyệt.
- **Hết phiên khi đang dùng:** query/mutation nhận 401 sau khi refresh thất bại → `createAppRouter` chuyển về `/login?redirect=…&expired=true` và xoá cache. Query/mutation có key `['auth', ...]` không đi qua đường này (401 của chúng là sai mật khẩu hoặc chưa đăng nhập).
- **404 chuyển vào `_app/$.tsx`** (route bắt mọi URL còn lại): 404 hiện trong layout và chỉ sau khi đăng nhập.
- **Sửa `<main>` lồng nhau** từ slice 1.1: `SidebarInset` của shadcn đã là `<main>`.
- **Bật `@typescript-eslint/no-deprecated`:** IDE báo `FormEvent` (React 19.3) deprecated mà lint không bắt; bật rule thì lộ thêm `ensureQueryData` (TanStack Query 5.105), đổi sang `SubmitEvent` và `queryClient.query()`.
- **Cho phép `throw redirect()`** của TanStack Router trong rule `@typescript-eslint/only-throw-error` (web).
- **`COOKIE_SECURE`** (mặc định `true`): Safari và trình duyệt mở qua `http://<IP>` bỏ cookie `Secure` trên HTTP; đặt `false` trong `.env` khi cần.
- **Stub `ResizeObserver` trong setup test web:** tooltip của Radix mở khi hover lâu, test chạy chậm thì crash.
- **Bundle:** `index.js` còn 266 kB (83 kB gzip), trước là 499 kB. Layout và các trang giờ nằm trong chunk riêng của route.

### Code review (`/code-review`, một vòng)

Đã sửa:

- Refresh thua cuộc đua (trong 30s grace, hoặc request song song đã xoay trước) vẫn xoá cookie, ghi đè cookie mới của request thắng → đăng xuất người dùng. Giờ ném `StaleRefreshError`, controller không xoá cookie
- Bí mật sai bất kỳ (chỉ cần biết id phiên) cũng thu hồi phiên → chỉ thu hồi khi đúng là token vừa bị thay, dùng lại sau 30s
- `Secure` cố định làm hỏng đăng nhập trên Safari, hoặc khi mở qua `http://<IP>` → thêm `COOKIE_SECURE`
- Nhiều query 401 cùng lúc gọi `expireSession` nhiều lần → chỉ lần đầu chạy
- `session-refresh.ts` gọi `fetch` trực tiếp, trái convention → thêm comment lý do (gọi qua `api()` sẽ refresh lồng nhau)
- Hash giả để cân thời gian được tạo lúc khởi động, lỗi thành unhandled rejection → tạo lười ở lần login đầu

Không sửa:

- Không có Web Locks thì các tab không refresh lần lượt: sau khi sửa điểm đầu, refresh thua cuộc đua không còn làm mất phiên
- Mở `/login` khi đã đăng nhập (sau khi reload) vẫn hiện form, đăng nhập lại tạo thêm một phiên: chấp nhận, kiểm tra thật sẽ gọi thêm `/auth/me` và refresh cho mọi lần mở trang login
- Refresh tốn 3 query (session, user, xoay vòng): nhỏ, tối ưu khi cần
- Pipe zod tự ghi `statusCode`, `error`: cần thiết, vì `BadRequestException(object)` dùng nguyên object làm body
