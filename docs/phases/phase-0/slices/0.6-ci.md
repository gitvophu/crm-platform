## Spec

### Mục tiêu

Mỗi PR và mỗi push lên `main` tự chạy format check, lint, typecheck, test, build trên GitHub Actions. ESLint chặn các import vi phạm ranh giới module (ADR-0001, ADR-0003), có test tự động chứng minh rule hoạt động. api và web dùng alias `@/*` thay cho `../`.

### Trong phạm vi

- Workflow GitHub Actions: 1 job chạy native trên runner, Postgres là service container, cache pnpm store và `.turbo`
- `eslint-plugin-boundaries` với 3 rule ranh giới, `import-x/no-cycle` cho import vòng giữa module
- Test Vitest chạy ESLint trên fixture, kiểm tra từng rule
- Alias `@/*` → `src/*` cho api và web, đổi các import `../` hiện có

### Ngoài phạm vi

- Bật branch protection (bắt PR phải xanh mới merge): bạn bật trong GitHub settings, README ghi cách làm
- Kiểm tra image dev hoặc `docker compose up` trong CI
- Deploy, release, Dependabot
- Rule "repository chỉ đụng model của schema mình": lint không thấy được, vẫn bắt khi review (ADR-0003)

### Tiêu chí hoàn thành

- [ ] Mở PR → workflow `CI` chạy và xanh, có link run
- [ ] Lần chạy thứ hai không đổi code: task được lấy từ cache của turbo (trừ test của api)
- [ ] Test fixture: mỗi import sai bị báo đúng rule, mỗi import đúng không bị báo. Làm hỏng config thì test đỏ
- [ ] api, web không còn import `../`. Build, test, dev server (`make up`) vẫn chạy
- [ ] `make lint typecheck test build` pass

## Q&A

Trạng thái: ❓ Mở (có đề xuất, chờ chốt) · ✅ Đã chốt.

### Q1. CI chạy trong môi trường nào?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Phương án:**
  - A: native trên runner: `actions/setup-node` đọc `.nvmrc`, `pnpm/action-setup` đọc `packageManager`, Postgres là service container
  - B: Docker + `make` như local. Phải build image mỗi lần, runner chạy UID 1001 trong khi volume `HOME` cố định UID 1000
- **Quyết định:** A.
- **Lý do:** nhanh, cache theo cách chuẩn. Version Node và pnpm vẫn lấy từ cùng nguồn với local. Đổi lại, CI không kiểm tra image dev.

### Q2. Công cụ kiểm tra ranh giới module?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Phương án:** `eslint-plugin-boundaries`, hoặc `dependency-cruiser`
- **Quyết định:** `eslint-plugin-boundaries` (v7) + `eslint-import-resolver-typescript` để hiểu alias.
- **Lý do:** chạy trong ESLint sẵn có, IDE báo lỗi ngay khi gõ import sai, dùng chung cache turbo, không thêm lệnh mới.

### Q3. Rule nào?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Quyết định:** cả 4:
  1. File trong `src/modules/<a>/` chỉ import module khác qua `src/modules/<b>/index.ts` (public API) (ADR-0001)
  2. Chỉ `*.repository.ts` import `PrismaService` và Prisma client sinh ra, ngoài chính `src/prisma/` (ADR-0003)
  3. `apps/web` và `apps/api` không import file của nhau. Code dùng chung đi qua `@crm/shared`
  4. Không import vòng giữa các module. `eslint-plugin-boundaries` không phát hiện vòng nên dùng `import-x/no-cycle`, chỉ bật cho `apps/api/src/modules/`

### Q4. Path alias cho api?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Phương án:**
  - A: tsconfig `paths` `@/*` → `src/*`
  - B: subpath imports `#src/*`. Lúc chạy trỏ `dist/`, lúc test trỏ `src/`, cần custom condition cho Vitest
  - C: giữ đường dẫn tương đối
- **Quyết định:** A.
- **Lý do:** Nest CLI chuyển `paths` cho SWC để đổi thành đường dẫn tương đối khi build (đã đọc source `swc-defaults.js`). Vitest dùng `resolve.tsconfigPaths` của Vite 8, ESLint dùng resolver TypeScript, `tsc` hiểu sẵn.

### Q5. Chứng minh "import chéo module thì CI đỏ"?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Phương án:** test tự động với fixture, PR demo cố ý vi phạm, hoặc cả hai
- **Quyết định:** test tự động với fixture.
- **Lý do:** api chưa có module nghiệp vụ nên chưa có gì để chặn. Fixture có 2 module mẫu với import đúng và sai, test chạy ESLint với config thật. Sau này sửa config làm hỏng rule thì test đỏ.

### Q6. Tổ chức workflow?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Phương án:** 1 job, hoặc mỗi bước 1 job song song
- **Quyết định:** 1 job, chạy khi có PR vào `main` và push lên `main`: install → `prettier --check` → `turbo run lint typecheck test build`. `concurrency` huỷ lần chạy cũ khi có push mới lên cùng PR.
- **Lý do:** chỉ cài dependency một lần, turbo tự chạy song song.

### Q7. Cache turbo trong CI?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Phương án:** `actions/cache` cho `.turbo`, chỉ cache pnpm store, hoặc Vercel Remote Cache
- **Quyết định:** `actions/cache` cho `.turbo/cache`, `setup-node` cache pnpm store.

### Q8. Alias cho web?

- **Trạng thái:** ✅ Đã chốt (2026-10-29)
- **Phương án:** chỉ api, hoặc cả api và web
- **Quyết định:** cả hai, cùng quy ước `@/*` → `src/*`. Web dùng `resolve.tsconfigPaths` của Vite 8.

## Ghi chú khi implement

Những gì lệch khỏi plan trong lúc làm, và lý do.

- **Phân loại phần tử:** `api`, `web`, `shared` khớp theo hậu tố đường dẫn (mặc định), không dùng `partialMatch: false`. Với `partialMatch: false`, phần tử `api` khớp luôn tới từng file nên file trong module bị xếp là `api`, còn `module` chỉ là parent. Khớp theo hậu tố thì phần tử gần file nhất thắng.
- **Rule Prisma viết thành 2 policy:** chặn mọi file trong module dùng `prisma`, rồi cho phép riêng file có category `repository` (policy khớp sau cùng thắng). Cách `categories: { noneOf: ['repository'] }` không chạy, vì file không có category nào thì `categories` là `null`.
- **`import-x` cần setting TypeScript:** lấy `importX.flatConfigs.typescript.settings` (parser, extensions). Thiếu thì `no-cycle` không đọc được file `.ts` được import và không báo gì.
- **`no-cycle` báo cả dòng re-export trong `index.ts`:** các file này cũng nằm trong vòng. Fixture đánh dấu thêm 2 dòng đó.
- **Root path:** turbo chạy `eslint .` trong từng package, nên đặt `boundaries/root-path` là thư mục gốc repo để pattern `apps/api/...` khớp.
- **Fixture:** `apps/api/test/boundaries/fixtures/src/` mô phỏng `src/` với 2 module `alpha`, `beta`, gồm các dòng vi phạm có comment `// ✗ <loại>`. Test so đúng danh sách `file:dòng loại` với các comment đó. Alias `@/` trỏ tới `src` thật nên giữa các file fixture dùng `../`. Fixture nằm trong `include` của tsconfig api (ESLint cần type info), nên phải typecheck được.
- **`unrs-resolver: false` trong `allowBuilds`:** dependency của `eslint-import-resolver-typescript`, postinstall chỉ kiểm tra binary native đã có sẵn qua optionalDependencies.
- **Workflow:** kiểm tra cú pháp bằng `actionlint` (chạy qua Docker image `rhysd/actionlint`).

- **Sau code review:**
  - `*.repository.test.ts` cũng thuộc category `repository`, để test của repository dựng được `PrismaService`.
  - Rule Prisma chỉ chặn import giá trị (`dependency: { kind: 'value' }`). Service, controller được `import type` model của Prisma (bạn chọn, đúng chữ ADR-0003: chặn `PrismaService` ngoài repository).
  - Regex chặn `../` bắt mọi đoạn `..` (`../x`, `..`, `./../x`).
  - Fixture không import file web thật nữa: thêm stub `fixtures/apps/web/` và `fixtures/packages/shared/` (khớp theo hậu tố nên được phân loại là web, shared). Có thêm case web → api và shared → api.
  - Marker ghi loại vi phạm (`public-api`, `prisma`, `cross-app`, `cycle`), test map message của ESLint sang loại, nên một policy hỏng không bị che bởi policy khác báo cùng dòng. Thử làm hỏng 5 policy: test đỏ cả 5.
  - CI gọi `pnpm lint` (script của root, giống `make lint`), rồi `turbo run typecheck test build`.
  - CI tỉa `.turbo/cache` trước khi lưu: chỉ giữ artifact có hash trong run summary (`--summarize`). Thử ở local: 231 file còn 36, lần chạy sau vẫn cache hit đủ.
  - Không sửa: test ranh giới chạy ESLint có type info (khoảng 2s) và nằm cùng suite với `globalSetup` reset DB. Tách ra thì phải thêm config Vitest riêng, chưa đáng.
