## Spec

### Mục tiêu

Từ clone sạch, `cp .env.example .env && docker compose up` là chạy được cả stack: tự cài dependency, build shared, migrate. Khi dev, sửa code api thì api tự restart, healthcheck của api và web phản ánh trạng thái thật để `make up` chờ đúng lúc stack sẵn sàng.

### Trong phạm vi

- Service `setup` chạy một lần mỗi lần `up`: `pnpm install --frozen-lockfile`, build `@crm/shared`, generate Prisma client, `prisma migrate deploy`
- api chạy `nest start --watch` (hot reload khi sửa `apps/api/src`)
- Healthcheck: api `GET /health` trả 200, web `GET /` trả 200
- `make restart`: chạy lại `setup` rồi tạo lại api, web (sửa `packages/shared`, hoặc pull khi stack đang chạy)
- Service `dev` không bị `docker compose up` bật lên
- Image dev tự build khi máy chưa có

### Ngoài phạm vi

- Tự watch `packages/shared` (Q4 chọn restart tay, ghi backlog)
- Bỏ bước `cp .env.example .env` (Q2 giữ bắt buộc)
- Compose cho production, image riêng cho từng app
- Tự restart container khi unhealthy

### Tiêu chí hoàn thành

- [ ] Clone sạch, máy chưa có image và volume: `cp .env.example .env && docker compose up -d --wait` chạy được, `localhost:5173` hiện `API: ok, DB: ok`
- [ ] Sửa file trong `apps/api/src` → api tự restart, không cần lệnh nào
- [ ] Sửa `apps/web/src` → HMR như slice 0.4
- [ ] Sửa `packages/shared` → `make restart` → api, web dùng code mới
- [ ] `make up` chỉ trả về khi api trả `/health` 200 và web trả 200
- [ ] Dừng api, web đều < 1s
- [ ] `make lint typecheck test build` pass

## Ghi chú khi implement

Những gì lệch khỏi plan trong lúc làm, và lý do.

- **`nest start --watch --no-shell`:** mặc định Nest CLI chạy app qua `sh -c node ...`. Khi reload, nó kill cả cây process bằng `ps`, nhưng image slim không có `ps` nên chỉ kill được `sh`. Process node cũ vẫn giữ cổng 3000, process mới lỗi `EADDRINUSE`. `--no-shell` spawn node trực tiếp nên kill trúng. Không cài thêm `procps` vào image.
- **`docker/healthcheck.mjs`:** viết `fetch` inline trong `test:` thì Prettier tách thành mảng nhiều dòng, khó đọc. Tách ra script nhỏ nhận URL, có timeout 2s.
- **`build` đặt trong anchor `x-node`:** mọi service dùng image dev đều có `build`, nên `up` tự build khi chưa có image. Compose build một lần cho cả các service dùng chung image.
- **`setup` dùng `turbo run @crm/shared#build @crm/api#generate`:** chỉ chạy đúng 2 task cần, có cache của turbo.
- **Sau code review:**
  - `make restart` chạy lại service `setup` (`docker compose run --rm setup`) rồi `up -d --wait --force-recreate --no-deps api web`. Bản đầu build shared trong container `dev`, có thể chạy cùng lúc với `setup` và ghi `dist` chồng lên nhau. Giờ `make restart` dùng được cả sau khi pull khi stack đang chạy, kể cả lúc api, web chưa có container. Mất khoảng 4s.
  - `make migrate` chạy lại `setup`, để logic migrate chỉ nằm một chỗ.
  - Cổng api, URL healthcheck, `API_PROXY_TARGET` của web lấy từ `PORT` (compose đọc `.env` để thay biến). Đã thử `PORT=3001`.
  - README: phiên bản Docker tối thiểu (Engine 25+ cho `start_interval`), UID khi gọi `docker compose` trực tiếp, khi nào dùng `make restart`.
  - Không sửa: `make build` khi api đang watch (đã thử, api vẫn chạy; nếu gặp lỗi thì tách thư mục output khi dev). `build` lặp ở các service dùng chung image (clone sạch đã thử: build được, không pull). Không viết test tự động cho `healthcheck.mjs` (11 dòng, đã kiểm tra qua `docker compose ps`).
- **`make build` khi api đang watch:** cả hai cùng ghi `apps/api/dist`. Đã thử: api vẫn healthy và vẫn reload bình thường.
