## Spec

### Mục tiêu

Dựng khung monorepo để mọi slice sau gắn vào: một lần `pnpm install` ở root, lint/format/typecheck/test/build chạy chung cho cả repo qua Turborepo.

### Trong phạm vi

- pnpm workspace + Turborepo với 4 task: `build`, `lint`, `typecheck`, `test`
- 3 package: `apps/api`, `apps/web`, `packages/shared`. App chỉ là placeholder TypeScript, chưa có framework
- `packages/shared` build ra `dist/` và được app import qua workspace
- TypeScript config gốc, ESLint + Prettier dùng chung
- Vitest cho cả repo, có 1 test mẫu trong `packages/shared`
- `.editorconfig`, `.nvmrc`

### Ngoài phạm vi

- NestJS (slice 0.2), Vite/React (slice 0.3)
- Docker (0.4), CI và kiểm tra ranh giới module (0.5)
- Git hooks (husky, lint-staged): xem Q11

### Q7. Phiên bản Node?

- **Trạng thái:** ✅ Đã chốt (2026-10-18) · Phần cài qua nvm bị thay thế bởi [ADR-0002](../../../adr/0002-dev-env-docker.md) (2026-10-21): Node chạy trong image dev. Version 26 và `.nvmrc` giữ nguyên
- **Phương án:**
  - A: Node 24 (Active LTS, máy đang dùng 24.21)
  - B: Node 26
- **Quyết định:** B. `.nvmrc` ghi `26`, `engines.node` là `>=26 <27`.
- **Bối cảnh (kiểm tra ngày 2026-10-18):** bản mới nhất là 26.12.0 (2026-10-14), **chưa chính thức lên LTS**, dự kiến lên cuối tháng 10/2026. Toàn bộ tool đã chọn đều hỗ trợ: Nest `>=20`, Vite `>=22.12`, typescript-eslint `>=21.1`, Vitest `>=26`.
- **Lý do:** dự án sống qua 2027. Chọn 26 ngay từ đầu để không phải nâng Node giữa chừng.

### Q8. `packages/shared` xuất ra ESM hay CommonJS?

- **Trạng thái:** ✅ Đã chốt (2026-10-18)
- **Phương án:**
  - A: ESM (`"type": "module"`, `module: nodenext`)
  - B: CommonJS
  - C: build cả hai (dual package)
- **Quyết định:** A.
- **Lý do:** Vite và frontend làm việc tự nhiên với ESM. Nếu NestJS ở 0.2 chạy CommonJS, Node 26 vẫn `require()` được package ESM (miễn là không dùng top-level await). Phương án C phức tạp không cần thiết.
- **Cần kiểm chứng ở 0.2:** Nest import `@crm/shared` chạy được cả khi dev lẫn khi chạy bản build. Nếu không được thì chuyển sang C và ghi lại ở đây.

### Q9. Mức độ ESLint?

- **Trạng thái:** ✅ Đã chốt (2026-10-18)
- **Phương án:**
  - A: `recommendedTypeChecked` của typescript-eslint
  - B: `strictTypeChecked`
  - C: `recommended` (không type-aware)
- **Quyết định:** A + `eslint-config-prettier` để tắt các rule đụng với Prettier.
- **Lý do:** type-aware bắt được lỗi thật (như promise bị bỏ quên) mà không quá ồn khi đang dựng khung. Có thể nâng lên B sau khi có module mẫu Contacts.

### Lệch so với plan

- **Bỏ `verbatimModuleSyntax` khỏi `tsconfig.base.json`.** Nếu NestJS ở 0.2 build ra CommonJS, option này buộc phải viết `import x = require(...)`. `isolatedModules` là đủ cho các tool build từng file.
- **`apps/api` khai báo `types: ["node"]`.** TS 6 đổi mặc định `types` thành `[]`, nên package nào cần type của Node phải khai báo rõ. Nhờ vậy `shared` và `web` không bị lẫn global của Node.
- **`turbo.json` có `globalDependencies`** gồm `tsconfig.base.json`, `eslint.config.mjs`, `vitest.config.ts`. Mặc định turbo chỉ hash file trong package, nên sửa config ở root sẽ không huỷ cache.
- **`shared` export `HealthResponse` + `isHealthy`** thay vì type mẫu chung chung. Đây là đúng shape `{ status, db }` mà `GET /health` ở 0.2 sẽ dùng.
- **App placeholder để `"type": "module"`.** Slice 0.2 sẽ chọn module format cho NestJS (xem Q8).
- **Prettier format lại toàn bộ docs Markdown** (căn cột bảng, `*x*` → `_x_`). Tách thành commit riêng để diff code dễ đọc.
