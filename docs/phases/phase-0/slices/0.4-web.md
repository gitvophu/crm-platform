## Spec

### Mục tiêu

Thay placeholder trong `apps/web` bằng app Vite + React thật. Trang chủ gọi `GET /health` qua TanStack Query và hiển thị trạng thái API, DB, dùng type `HealthResponse` từ `@crm/shared`. Từ đây Phase 1 có khung frontend để gắn màn hình vào.

### Trong phạm vi

- Vite 8 + React 19 + TanStack Query 5 trong `apps/web`
- Gọi API qua Vite proxy: `/api/*` → `http://api:3000/*`
- Trang chủ hiển thị 3 trạng thái: `API: ok, DB: ok` · `API: ok, DB: error` · `API: không kết nối được`, tự cập nhật mỗi 10s
- Service `web` tối thiểu trong compose (Vite dev server, cổng `127.0.0.1:5173`), `make up` chạy cả postgres, api, web
- Component test với Vitest + jsdom + Testing Library + MSW
- ESLint cho React (`react-hooks`, `react-refresh`)

### Ngoài phạm vi

- Router, layout, design system, thư viện UI/CSS (Phase 1, ghi backlog)
- Serve bản build production của web (nginx, CDN)
- Healthcheck cho service web, `docker compose up` từ clone sạch (slice 0.5)
- Thay đổi API (route `/health` giữ nguyên, không thêm global prefix)

### Tiêu chí hoàn thành

- [ ] `make up` → mở `http://localhost:5173` thấy `API: ok, DB: ok`
- [ ] Dừng postgres → trong ≤ 10s trang chuyển sang `DB: error`, không cần reload
- [ ] Dừng api → trang hiển thị `API: không kết nối được`
- [ ] Sửa một file `.tsx` → trình duyệt cập nhật ngay (Vite HMR qua bind mount)
- [ ] `make lint typecheck test build` pass, có component test cho cả 3 trạng thái
- [ ] Type `HealthResponse` lấy từ `@crm/shared`, không khai báo lại trong web

### Q1. Web gọi API thế nào khi dev?

- **Trạng thái:** ✅ Đã chốt (2026-10-25)
- **Phương án:**
  - A: Vite proxy, web gọi `/api/health` cùng origin, Vite bỏ prefix `/api` rồi chuyển sang api
  - B: bật CORS trên API, web gọi thẳng `http://localhost:3000` qua biến `VITE_API_URL`
- **Quyết định:** A.
- **Lý do:** không cần CORS hay biến URL. Production sau này dùng reverse proxy theo cùng cách nên code web không đổi.

### Q2. Chạy web để demo thế nào?

- **Trạng thái:** ✅ Đã chốt (2026-10-25)
- **Phương án:**

  - B: `make web` tạm thời qua `docker compose run --service-ports`
- **Quyết định:** A, giống cách làm với api ở slice 0.3.
- **Hệ quả:** slice 0.5 còn lại healthcheck, hot reload cho api và `docker compose up` từ clone sạch.

### Q3. Xử lý 503 từ `/health` thế nào?

- **Trạng thái:** ✅ Đã chốt (2026-10-25)

- **Quyết định:** A.
- **Lý do:** phân biệt được DB lỗi (API vẫn sống) với API không kết nối được.

## Ghi chú khi implement

Những gì lệch khỏi plan trong lúc làm, và lý do.

- **MSW 3 đổi tên option:** `server.listen({ onUnhandledRequest })` thành `onUnhandledFrame` (gộp cả request và WebSocket). Đặt `'error'` để test gọi URL chưa mock thì fail ngay.
- **`retry: false` trong `useQuery`:** mặc định TanStack Query thử lại 3 lần với backoff (khoảng 7s) trước khi báo lỗi, nên API chết sẽ hiện chậm. Health check tự refetch mỗi 10s nên không cần retry.
- **Tách tsconfig:** `tsconfig.json` chỉ reference `tsconfig.app.json` (`src/`, `types: ["vite/client"]`) và `tsconfig.node.json` (`vite.config.ts`, `types: ["node"]`), giống template của Vite. Code trong `src/` dùng `process` sẽ bị typecheck báo lỗi. Script `typecheck` đổi thành `tsc -b`.
- **API chết qua proxy:** Vite trả 502 (`getaddrinfo ENOTFOUND api`), `fetchHealth` coi là lỗi → `API: không kết nối được`, đúng Q3.
- **Service web chạy `node_modules/.bin/vite` thay vì `pnpm dev`:** `exec` thẳng vào Vite để nhận SIGTERM, `docker compose stop web` mất 0,22s.
- **Sau code review:**
  - `fetchHealth` kiểm tra shape của body, không ép kiểu. Một 503 không phải `HealthResponse` (ví dụ lỗi chuẩn của Nest `{statusCode, message}`) hiện là `API: không kết nối được`, thêm 1 test cho trường hợp này.
  - `make up` build `@crm/shared` trước khi bật service. api và web đều build shared lúc khởi động, cache miss thì hai container ghi `dist/` cùng lúc. Turbo cache hit không ghi lại file nên sau bước này không còn race.
  - README: chạy lại `make install` sau khi pull, biến `API_PROXY_TARGET`.
  - Không sửa: trạng thái chuyển sang "không kết nối được" ngay khi 1 lần refetch lỗi. Health check phải phản ánh trạng thái hiện tại.
- **Version:** `pnpm add` với version cụ thể ghi ghim cứng, đã đổi sang `^` cho giống các package khác.
