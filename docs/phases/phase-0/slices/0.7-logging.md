## Spec

### Mục tiêu

api ghi log JSON, mỗi dòng log trong một request mang request-id, id được trả về trong header `X-Request-Id`. CLAUDE.md có convention thật của Phase 0. Viết `review.md` của Phase 0 với số liệu đo lại có điều kiện rõ, rồi tag `phase-0`. Đây là slice cuối của Phase 0.

### Trong phạm vi

- `nestjs-pino`: log JSON cho cả log của Nest và log request
- Request-id: nhận `X-Request-Id` hợp lệ hoặc tạo UUID, trả về trong header response, có trên mọi dòng log của request
- Không log `/health` khi trả 200
- Biến `LOG_LEVEL` (validate bằng zod)
- CLAUDE.md: cấu trúc module, đặt tên, test, logging. Format lỗi API ghi "chốt ở slice 1.2"
- `review.md` Phase 0: đối chiếu Definition of Done, số liệu, ADR, retro
- Tag `phase-0` sau khi merge

### Ngoài phạm vi

- Format body lỗi API, global exception filter (slice 1.2, ghi backlog)
- Web gửi hoặc hiển thị request-id
- Log của web, gom log tập trung (Loki, ELK), tracing (OpenTelemetry)
- `pino-pretty` (Q3: luôn JSON)

### Tiêu chí hoàn thành

- [ ] `curl -i localhost:3000/<route>` → header `X-Request-Id`, log api có dòng JSON chứa cùng id
- [ ] Gửi `X-Request-Id: abc-123` → response và log dùng lại `abc-123`. Gửi giá trị sai format → id mới
- [ ] Log của Nest (khởi động, `Logger` trong controller) là JSON. Log trong request có `reqId`
- [ ] `/health` 200 không sinh log request, 503 có log mức warn
- [ ] CLAUDE.md không còn TODO, trừ format lỗi API (chỉ rõ chốt ở slice 1.2)
- [ ] `review.md` điền đủ, có số liệu đo
- [ ] `make lint typecheck test build` pass, CI xanh

## Q&A

Trạng thái: ❓ Mở (có đề xuất, chờ chốt) · ✅ Đã chốt.

### Q1. Logger?

- **Trạng thái:** ✅ Đã chốt (2026-10-31)
- **Phương án:**
  - A: `nestjs-pino`: request log, request-id trên mọi dòng log (AsyncLocalStorage), redact, bỏ log theo điều kiện đều có sẵn qua cấu hình
  - B: `ConsoleLogger({ json: true })` của Nest (có từ Nest 11) + tự viết middleware, AsyncLocalStorage, redact
  - C: pino + tự viết phần request-id
- **Quyết định:** A.
- **Lý do:** phần khó nhất là gắn request-id vào mọi dòng log, kể cả `new Logger()` trong service. nestjs-pino làm sẵn, code hiện có không phải đổi. Đổi lại thêm 3 package (`nestjs-pino`, `pino`, `pino-http`).

### Q2. Request-id lấy từ đâu?

- **Trạng thái:** ✅ Đã chốt (2026-10-31)
- **Phương án:** nhận header `X-Request-Id` nếu hợp lệ, không thì tạo; hoặc luôn tự tạo
- **Quyết định:** nhận nếu hợp lệ (tối đa 128 ký tự, chỉ gồm chữ, số, `-_.`), không thì tạo UUID. Luôn trả về trong header `X-Request-Id`.
- **Lý do:** reverse proxy hoặc service khác (Phase 2 trở đi) truyền được id xuyên suốt. Giới hạn format để client không chèn được giá trị lạ vào log.

### Q3. Format log khi dev?

- **Trạng thái:** ✅ Đã chốt (2026-10-31)
- **Phương án:** JSON có tuỳ chọn pretty, pretty khi dev, hoặc luôn JSON
- **Quyết định:** luôn JSON, không cài `pino-pretty`. Muốn đọc dễ thì pipe qua `jq`.

### Q4. Log request tới `/health`?

- **Trạng thái:** ✅ Đã chốt (2026-10-31)
- **Phương án:** chỉ log khi lỗi, hoặc log tất cả
- **Quyết định:** `/health` trả 200 thì không log request, 503 log mức warn.
- **Lý do:** healthcheck của compose và web gọi `/health` khoảng 12 lần mỗi phút, sẽ lấn hết log khác.

### Q5. Format lỗi API?

## Ghi chú khi implement

Những gì lệch khỏi plan trong lúc làm, và lý do.

- **Tên file `logger.params.ts`** (plan ghi `logger.options.ts`): trả về `Params` của nestjs-pino, đặt tên theo type đó.
- **Bỏ `err` giả của pino-http cho 5xx:** với response 5xx, pino-http ghi `"request errored"` kèm một `err` tự tạo, stack chỉ trỏ vào code của pino-http. Trong Nest, lỗi thật đã được `ExceptionsHandler` log riêng (có `reqId`, stack thật), nên bỏ `err` giả qua `customErrorObject`. Test kiểm tra lỗi 500 có đúng 2 dòng: dòng của `ExceptionsHandler` và dòng `request errored`.
- **Message của request lỗi** là `request errored` (mặc định của pino-http cho 5xx), không phải `request completed`.
- **Log text của Nest CLI:** khi dev, `nest start --watch` in vài dòng text (`SWC Running...`). Đó là output của CLI, không phải log của app. README hướng dẫn lọc bằng `grep '^{'`.
- **Test logging** dựng app nhỏ với controller giả và logger ghi vào bộ nhớ (`loggerParams('info', destination)`), không dùng `AppModule`, để kiểm tra từng dòng log. Test của `AppModule` kiểm tra header `X-Request-Id` có trên `/health`.
