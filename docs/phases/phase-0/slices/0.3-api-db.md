## Spec

### Mục tiêu

Dựng app NestJS thật trong `apps/api`, nối PostgreSQL qua Prisma, có migration đầu tiên. `GET /health` trả trạng thái API và DB. Từ đây các module nghiệp vụ của Phase 1 có chỗ để gắn vào.

### Trong phạm vi

- NestJS 12 (ESM) thay cho placeholder trong `apps/api`, build bằng Nest CLI + SWC
- Prisma 7 + `@prisma/adapter-pg`, schema chia file theo module, client sinh ra qua task `generate` của turbo
- Migration đầu tiên: tạo schema `contacts` rỗng cho module mẫu
- Config qua env, validate bằng zod
- `GET /health` trả `HealthResponse` (`@crm/shared`): 200 khi DB ok, 503 khi DB lỗi
- Compose: service `postgres:18` (có healthcheck, DB `crm` và `crm_test`) và service `api` tối thiểu (chạy được, mở cổng 3000)
- `.env.example`, Makefile thêm `up`, `down`, `migrate`, `migration`
- Test: Vitest + `unplugin-swc`, unit test cho config, integration test `/health` với DB thật
- ADR-0003, sửa `review-checklist.md` (bỏ yêu cầu down migration, xem Q5)

### Ngoài phạm vi

- Module nghiệp vụ, bảng dữ liệu thật (Phase 1)
- Hot reload và healthcheck cho service `api`, service `web` (slice 0.5)
- Lint ranh giới module (slice 0.6)
- Logging, request-id (slice 0.7)
- Format lỗi API chung (chốt khi làm Contacts)

### Lệch so với plan

- **`pnpm-workspace.yaml` có thêm `allowBuilds`** cho `@prisma/engines`, `prisma`, `@swc/core`. pnpm 12 mặc định chặn build script của dependency (`ERR_PNPM_IGNORED_BUILDS`).
- **Prisma cảnh báo Node 26 chưa được hỗ trợ** lúc cài (script `preinstall`: "only supports 20.19+, 22.12+, 24.0+"), dù `engines` của `@prisma/client` ghi `>=24.0`. `generate`, `migrate` và client đều chạy đúng trên Node 26.12. Nếu gặp lỗi lạ từ Prisma thì nghi ngờ điểm này trước.
- **Migration init viết tay.** `prisma migrate dev --create-only` sinh ra file rỗng vì chưa có model, nên tự viết `CREATE SCHEMA IF NOT EXISTS "contacts"`.
- **Container `dev` không `depends_on` postgres.** Chỉ `make test`, `make migrate`, `make migration` tự bật postgres (`docker compose up -d --wait postgres`), để `make lint`/`typecheck`/`build` không phải chờ DB.
- **Test ép `DATABASE_URL` = `TEST_DATABASE_URL`** qua `test.env` trong `vitest.config.ts`, để test không bao giờ đụng DB dev. Turbo chỉ cho task `test` thấy hai biến này (`passThroughEnv`).
- **Test 503 dùng `vi.spyOn(PrismaService.ping)`** thay vì dừng DB thật. Trường hợp DB dừng thật đã kiểm tra tay (bảng trên).
- **`PrismaPg` đặt `connectionTimeoutMillis: 2000`.** Mặc định của `pg` là chờ vô hạn khi DB không phản hồi, khiến `/health` treo thay vì trả 503.
- **`apps/api/tsconfig.json` chỉ dùng để typecheck** (`noEmit`, gồm cả `test/` và file config). Build do SWC làm.
- **Service `api` dùng `init: true` và `exec node dist/main.js`** thay vì `pnpm --filter @crm/api start` (sửa sau khi đã commit lần đầu). Với lệnh cũ, PID 1 là `sh` và app nằm sau 4 lớp process (`pnpm` → `pnpm-native` → `sh`), nên SIGTERM không tới được node: `docker compose stop api` mất 10.24s và kết thúc bằng SIGKILL (exit 137), shutdown hook của Nest không chạy. Sau khi sửa: stop mất 0.19s, exit 143 (Nest tự kết thúc bằng SIGTERM sau khi chạy hook), đã kiểm tra bằng log tạm thời rằng `onModuleDestroy` của `PrismaService` có chạy.
- **Import `supertest/types.js` có đuôi `.js`.** `@types/supertest` không có trường `exports`, nên với `nodenext` phải ghi rõ đuôi.

### Sửa sau code review (2026-10-24)

Review bằng subagent (`/code-review`). Các điểm đã sửa:

- **`ping()` có timeout 2s.** `connectionTimeoutMillis` không áp dụng cho kết nối đã mở. Tái hiện bằng `docker compose pause postgres`: `/health` treo vô hạn. Sau khi sửa: trả 503 sau 2.0s. Có unit test `prisma.service.test.ts`.
- **`/health` log lý do khi DB lỗi** (`Logger.warn`).
- **Không cache `@crm/api#test`** trong turbo: test phụ thuộc DB, cache có thể báo pass trong khi DB hoặc migration đã hỏng.
- **Test từ chối reset DB không có hậu tố `_test`**, tránh xoá nhầm DB dev.
- **`restoreMocks: true`** trong Vitest.
- **Cổng 5432 và 3000 chỉ bind `127.0.0.1`**, không mở ra mạng LAN.
- **`make migration` kiểm tra `NAME`** theo `^[a-z0-9_]+$`.
- **Lỗi tự phát hiện thêm khi chạy lại test:** SWC build cả file `*.test.ts` ra `dist/`, và Vitest chạy luôn bản build. Sửa: Nest build dùng `tsconfig.build.json` loại trừ `src/**/*.test.ts`, Vitest bỏ qua `dist/**`.

Chưa sửa, có lý do:

- **`docker compose up` từ clone sạch lỗi** vì chưa có `node_modules` và chưa migrate. Đúng phạm vi tối thiểu của Q10; xử lý ở slice 0.5 (đã thêm vào việc cần làm).
- **Service `api` và `make build` cùng ghi `apps/api/dist`** nếu chạy cùng lúc. Hiếm gặp; slice 0.5 đổi api sang watch mode.
- **503 nhưng body có `status: "ok"`**: đúng spec. `status` là trạng thái process api, `db` là của DB, mã HTTP mới là tín hiệu tổng.
